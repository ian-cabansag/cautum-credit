CAUTUM CREDIT / REVIEWER KIT

Can you explain
the change?

Three relatable lender-review questions, with constructed aggregate source files and reproducible worked answers. These are fictional scenarios, not customer case studies. No patient information or client data is permitted.

The calculation policy is illustrative and unvalidated. Model attribution does not establish cash collections, losses, legal eligibility or a lending decision. There is no claim of independent user validation.

Try the workflow.

  1. Run Cautum using the repository README. These deterministic tasks need no model key.
  2. Open the local app, choose Changes, then select each example from Explore a lender question.
  3. Explain the sign of the base change, select the borrower and inspect the paired inputs. State which facts the model cannot establish.
  4. Export the borrower evidence packet and ask another reader to reproduce the contribution from the original inputs.
CONSTRUCTED EXAMPLE

More receivables, less modeled backing

A fictional community clinic reports $120,000 of receivables after $100,000 last period. Its 91+ balance is now $60,000 rather than $20,000. A lender needs to understand why a larger headline balance can support a smaller illustrative base.

Review question: Which aging cohorts changed, and what does the current policy do to them?

Compare the two source schedules before discussing availability. Changes between aggregate aging buckets do not prove that the same claims aged or that cash was collected.

CONSTRUCTED EXAMPLE

Same billing, a changed denial assumption

A fictional imaging practice reports the same $100,000 balance in both periods, but changes its modeled denial input from 5% to 15%. The reported receivables have not fallen, while the illustrative base has.

Review question: Is the changed denial input supported, and is that loss already included in the collection factor?

The calculation isolates the effect of an input change. It cannot verify denial outcomes, establish a recovery forecast or resolve double counting without source definitions.

CONSTRUCTED EXAMPLE

A payer rename with continuous identity

A fictional therapy group changes the payer label in its export from Example Health Plan to Example Health Network. Both manifests deliberately use one stable payer ID, and the $50,000 balance and assumptions are unchanged.

Review question: Does the mapped identity preserve the same exposure without inventing an addition, removal or collection?

Only an explicit map establishes this continuity. Similar names are not enough. Different IDs would remain separate added and removed balances until reviewed.

A future independent review

No participant results are embedded in this kit. Ask a willing reviewer to record their actual role and permission before sharing any observation. A student, founder or analyst must be identified accurately.

For a paired comparison, use identical constructed inputs and policy in the reference process and Cautum. Record all preparation, timing, errors, assistance and failures. Counterbalance order across reviewers when possible. A repeated task has learning effects; one faster result does not establish causal savings.

Questions: Which answer could you not verify? Which source-owner question is missing? Which step was confusing? Would this replace a real step in your current process? What would block adoption?
